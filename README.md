# «Орбита» — студенческий астроклуб

[![Deploy Orbita site](https://github.com/Qwel72/lab5-site/actions/workflows/deploy.yml/badge.svg)](https://github.com/Qwel72/lab5-site/actions/workflows/deploy.yml)

Учебный лендинг из ЛР №4, доработанный в лабораторной №5 по Git. Все встречи и заявки демонстрационные. Сайт не регистрирует пользователей, не отправляет и не хранит данные формы.

## Состав
- `index.html` — структура и текст;
- `styles.css` — оформление и адаптивная сетка;
- `script.js` — доступное мобильное меню, локальная проверка и очистка формы;
- `images/` — три реальные фотографии Земли, Луны и Юпитера с проверенными источниками;
- `docs/` — промпты, источники фотографий и результаты работы.

## Ветки
- `lab4-original` — неизменённый HTML, полученный для ЛР №4;
- `main` — основная версия, сначала коммит с очисткой формы и разделением файлов, затем merge;
- `feature/space-photos` — отдельная разработка галереи с тремя локальными фотографиями.

Ветка с фотографиями сохраняется после слияния. Использовано `git merge --no-ff`, поэтому merge-коммит имеет двух родителей. Историю можно просмотреть командой `git log --graph --oneline --all`.

## Локальный просмотр

Можно открыть `index.html` в современном браузере. Для проверки через локальный HTTP-сервер, если установлен Python 3, выполните в папке проекта:

```sh
python -m http.server 8000
```

Откройте http://localhost:8000/ . Сервер останавливается Ctrl+C. Зависимостей, сборки, CDN и backend у сайта нет.

## GitHub Pages

Репозиторий: https://github.com/Qwel72/lab5-site

Начиная с ЛР №6, в **Settings → Pages** выбран источник **GitHub Actions**. Собственный workflow `.github/workflows/deploy.yml` запускается при push в `main`. Сначала проходят проверки, затем готовится артефакт `_site`, после чего выполняется публикация. Ручной запуск для обычного обновления не нужен.

Опубликованный и проверенный сайт: https://qwel72.github.io/lab5-site/ . До ЛР №6 сайт публиковался из ветки `main` и `/(root)`. В ЛР №6 он переведён на собственный workflow GitHub Actions. Проверены HTTP 200 и совпадение SHA-256 HTML/CSS/JS и трёх фотографий с локальным проектом.


## Изображения

Кредиты и условия использования — `images/README.md`; точные URL и SHA-256 локальных JPEG — `docs/image-sources.json`. Фотографии иллюстрируют космос и не являются снимками клуба. NASA не является партнёром проекта и не одобряет его.

## Лабораторная №6: CI/CD

Индивидуальная часть — проверки качества до публикации: HTML (`html-validate`), CSS (`stylelint`), синтаксис JavaScript, целостность локальных ссылок и защита демо-формы. Отдельные отрицательные тесты проверяют, что линтеры отвергают HTML без `alt` и CSS с опечаткой `colro`.

Последовательность: `quality → build → deploy`. Если `quality` падает, зависимые задания не публикуют сайт. При `pull_request` выполняются только проверки. Для `push` в `main` и необязательного ручного запуска разрешена публикация. Actions закреплены по SHA; зависимости линтеров — через `package-lock.json` и `npm ci --ignore-scripts`.

Локальная проверка (Node.js >=20.19 и Python 3):

```sh
npm ci --ignore-scripts
npm run lint
npm run test:site
npm run build
```

В `_site` копируются только HTML, CSS, JavaScript, JPEG и `.nojekyll`. Документация, история Git, зависимости и исходники тестов не публикуются. `deployment.json` содержит SHA коммита и номер запуска: по нему можно сверить опубликованную версию. Персональные данные туда не добавляются. Для публикации не нужны личный токен GitHub, пароль или секрет Vercel — workflow использует штатную авторизацию Pages.

Ветка `lab5-final` сохраняет состояние сайта до перехода к ЛР №6; её история не переписывается.

Подтверждение ЛР №6: [описание CI/CD](docs/lab6-ci.md), [проверка публикации](docs/lab6-verification.json). Старый `docs/pages-verification.json` относится к состоянию ЛР №5.
